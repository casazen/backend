## STEP 1-2 — Lettura Parallela Backend + Frontend

> ⚡ **PARALLELIZZAZIONE**: Esegui lettura backend e frontend **in parallelo** (agenti indipendenti)

### Task A: Lettura Backend

**Repository**: `casazen/backend`

**File da leggere**:
1. `API_DOCUMENTATION.md`
2. Tutti i file `.cs` in `Casazen.Web/Controllers/`
3. Tutti i file `.cs` in `Casazen.Core/` (Entities, DTOs, Enums)

**Estrai**:
- Endpoint HTTP: metodo + path + request body + response model
- DTOs: nome + campi + tipi C#
- Enums: valori possibili
- Pattern error response: formato errori standard
- Parametri paginazione/filtro: PageNumber, PageSize, SortBy, etc.

### Task B: Lettura Frontend

**Repository**: `casazen/frontend`

**File da leggere**:
1. Tutti i file in `src/types/`
2. Tutti i file in `src/api/`
3. Tutti i file in `src/queries/`
4. `src/config/` e `.env.example`

**Estrai**:
- Interfacce TypeScript: nome + campi + tipi TS
- Chiamate API: path + metodo HTTP + body + tipo ritorno
- Gestione Auth0: token, configurazione
- Base URL: configurata in config o .env

**Invocazione Parallela**:
```markdown
Invoca in un'unica risposta:
- Task tool: agente Explore per backend
- Task tool: agente Explore per frontend
```

**Attendi completamento** di entrambi prima di procedere a Step 3.

## STEP 3 — Gap Analysis

Confronta Step 1 e 2, identifica disallineamenti per categoria:

### A — TypeScript Types

**Disallineamenti**:
- ❌ Interfaccia TS **mancante** per un DTO backend esistente
- ❌ Campo **mancante** in un'interfaccia TS esistente (presente nel DTO backend)
- ❌ Campo con **tipo incompatibile** (es. `string` vs `number`)
- ❌ Interfaccia TS **obsoleta** (DTO non più esistente nel backend)

### B — API Client (`src/api/`)

**Disallineamenti**:
- ❌ Endpoint backend **senza** corrispondente funzione nel frontend
- ❌ Path, metodo HTTP o body payload **errati** rispetto al backend
- ❌ Response type **incompatibile** con DTO backend

### C — React Query Hooks (`src/queries/`)

**Disallineamenti**:
- ❌ Funzione API in `src/api/` **senza** hook `useQuery`/`useMutation`
- ❌ Hook esistente con parametri **incompatibili** con funzione API

### D — Configurazione

**Disallineamenti**:
- ❌ Base URL non allineata tra frontend e backend
- ❌ Variabili `.env.example` **mancanti** per Auth0, API endpoint, etc.
- ❌ Auth0 non configurato (domain, audience, clientId mancanti)

### E — Documentazione Backend

**Disallineamenti**:
- ❌ Endpoint nei controller **non documentato** in `API_DOCUMENTATION.md`
- ❌ Endpoint **documentato** ma **non più esistente** nel codice

## STEP 4 — Apertura Issue GitHub (Batch Parallelo)

> ⚡ **PARALLELIZZAZIONE**: Crea issue in **batch parallelo** (max 10 issue per batch)

Per ogni disallineamento trovato, apri **una GitHub Issue** sulla repo corretta con l'agente @github_agent:

**Strategia Batch**:
1. Raggruppa disallineamenti per repository (frontend vs backend)
2. Crea issue in batch di massimo 10 contemporaneamente
3. Attendi completamento batch prima di procedere al successivo

| Categoria      | Repository Target      | Note                          |
|----------------|------------------------|-------------------------------|
| A, B, C, D     | `casazen/frontend`     | Fix nel frontend              |
| E              | `casazen/backend`      | Fix nella docs backend        |
| Naming conflict | **Entrambe le repo**   | Cross-reference, decisione umana richiesta |

### Formato Issue

**Titolo**: `[Sync] <Categoria> — <descrizione breve>`

**Esempi**:
- `[Sync] Type — Missing TypeScript interface for BookingResponseDto`
- `[Sync] API Client — POST /bookings uses wrong payload shape`
- `[Sync] Docs — GET /ota/sync not documented in API_DOCUMENTATION.md`
- `[Sync] Naming — Backend uses 'nightlyRate', Frontend uses 'pricePerNight'`

**Body Template**:
```markdown
## Categoria
<A/B/C/D/E>

## Severità
<🔴 Breaking / 🟡 Warning / 🔵 Info>

## Descrizione
<Cosa non è allineato>

## Backend (Source of Truth)
<Mostra signature/DTO dal backend>

## Frontend (Attuale)
<Mostra interfaccia/funzione frontend>

## Fix Proposto
<Cosa cambiare nel frontend/backend per allineare>

## File Coinvolti
- Backend: `path/to/file.cs`
- Frontend: `src/path/to/file.ts`

---
🤖 Generated by @scrum_master_casazen via Contract Audit
```

### Severità

- 🔴 **Breaking**: Frontend chiama endpoint con firma **sbagliata** → runtime error garantito
- 🟡 **Warning**: Campo **mancante** nel tipo TS → possibile `undefined` silenzioso
- 🔵 **Info**: Docs non aggiornata, hook mancante, config minore

## NOTE OPERATIVE

### Regole Audit

- ✅ **Backend è source of truth**: in caso di dubbio, il backend ha ragione
- ✅ **Naming conflict** → issue su **entrambe le repo** con cross-reference, richiedere decisione umana
- ✅ **File troppo grande** → annota nella issue che la lettura era parziale
- ❌ **NO duplicati**: se due disallineamenti riguardano lo stesso endpoint, consolida in una issue
- ❌ **NO codice modificato**: questo è solo audit, le fix verranno implementate dopo
- ❌ **NO branch o PR**: solo issue creation
- ✅ **Parallelismo agenti**: Usa agenti in parallelo quando possibile, ma **un solo agente per ciclo completo** (no sottoprocessi paralleli dentro lo stesso workflow)

### Lettura Repository Remote

Se le repository non sono clonate localmente:
- Usa GitHub MCP tools per leggere file remoti
- Se un file è > 1000 righe, leggi solo le parti rilevanti (es. solo i controllers)

### Output Atteso

Al termine dell'audit:
- ✅ N issue singole aperte (una per disallineamento)
- ✅ 1 issue riepilogativa aperta su backend
- ✅ Report testuale in CLI con link alle issue
