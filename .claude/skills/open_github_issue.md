# Skill: Open GitHub Issue - Create Issue via gh CLI

## Description
This skill describes how to create GitHub issues in a structured way using the `gh` CLI. It includes templates, labels, and best practices for regulatory compliance issues.

> **Cross-project reusable**: this skill works with any GitHub repository accessible via `gh` CLI.

## When to Use It
- When the `github_agent` needs to create issues from gap analysis
- When structured issues must be created programmatically
- When existing issues need to be updated with new information

## Prerequisites
Verify that the `gh` CLI is available and authenticated:

    gh auth status

## Procedure

### Step 1: Check for Duplicates
Before creating an issue, search for duplicates:

    gh issue list --search "keyword1 keyword2" --state open --json number,title

If you find a similar issue, evaluate whether:
- To add a comment instead of creating a new issue
- The existing issue already covers the requirement

### Step 2: Label Preparation
Ensure that required labels exist:

    gh label create "regulatory" --description "Regulatory compliance" --color "d93f0b" 2>/dev/null || true
    gh label create "compliance" --description "Compliance gap" --color "fbca04" 2>/dev/null || true

### Step 3: Create Issue
Use the `gh issue create` command with a heredoc for the body:

    gh issue create \
      --title "[COMPLIANCE] Descriptive gap title" \
      --label "regulatory,compliance,priority:high" \
      --body "$(cat <<'ISSUE_EOF'
    ## User Story
    As a **[role]**, I want **[action]**, so that **[benefit]**.

    ## Regulatory Context
    - **Reference**: [law/decree]
    - **Effective date**: [date]
    - **Penalties**: [description]

    ## Current State
    [description of what exists in the codebase]

    ## Implementation Requirements
    - [ ] [requirement 1]
    - [ ] [requirement 2]

    ## Acceptance Criteria
    - [ ] [criteria 1]
    - [ ] [criteria 2]

    ## References
    - [regulatory source link]

    ---
    _Issue generated by the Regulatory Intelligence system_
    ISSUE_EOF
    )"

### Step 4: Capture Output
Capture the created issue number to update tracking:

    ISSUE_URL=$(gh issue create --title "..." --body "..." 2>&1)
    echo "$ISSUE_URL"

### Step 5: Add Comments (optional)
To add information to existing issues:

    gh issue comment ISSUE_NUMBER --body "Update: [description]"

### Step 6: Close Issue (when resolved)

    gh issue close ISSUE_NUMBER --comment "Implemented in PR #XX"

## Naming Conventions

### Issue Titles
- `[COMPLIANCE] Implement CIN code management`
- `[COMPLIANCE] Update OTA withholding tax calculation to 21%`
- `[COMPLIANCE] Verify GDPR guest consent compliance`

### Labels
- `regulatory` - regulatory requirement
- `compliance` - compliance gap
- `priority:critical` - obligation in force, immediate penalties
- `priority:high` - obligation in force, penalties applicable
- `priority:medium` - moderate risk
- `priority:low` - best practice or future obligation

## Limits and Precautions
- Maximum 10 issues per execution
- Never create duplicate issues
- Always verify `gh` authentication before proceeding
- If creation fails, log the error and continue
- Never include credentials or sensitive data in issue bodies

## Error Handling

    # If gh is not authenticated
    if ! gh auth status &>/dev/null; then
      echo "ERROR: gh CLI not authenticated. Run 'gh auth login'"
      exit 1
    fi

    # If issue creation fails
    if ! gh issue create --title "..." --body "..." 2>/tmp/gh_error.log; then
      echo "ERROR creating issue: $(cat /tmp/gh_error.log)"
    fi
