# Runbook: public domain, canonical URLs, sitemap and robots.txt

Task SE-02, audit defect A8-02 (P0), decision D3: the public domain is configurable and **no domain is written in
code** (no default in `appsettings.json`, `vercel.json` or the sources). The code is in place; the product owner
chooses the domain, sets the variables of section 2 and follows sections 3 and 4.

## What the code does

| Concern | Behaviour | Code |
|---|---|---|
| Public domain (backend) | **One source**: `App__PublicSiteBaseUrl`, the URL of the web app of the environment. `Seo__PublicBaseUrl` is accepted as an alias and used only when `App__PublicSiteBaseUrl` is empty; both set with **different** values stop the startup. The SEO pages are routes of the same web app (`/p/…`), so a second domain would only produce canonicals that the app does not serve | `Casazen.Infrastructure/Email/PublicSiteOptions.cs` |
| What uses it | Email links (FD-13), the `canonicalUrl` of every SEO page, the hub canonical, every `<loc>` of the sitemap, the CORS origin of the web app | `PublicSiteLinks`, `SeoPagePaths`, `SeoContentService`, `CorsOriginOptions.AddPublicSiteOrigin` |
| Startup check | Outside `Development`/`Testing` (both Railway environments run `Production`) a missing, invalid or non-https value stops the startup, and Railway keeps the previous deployment. `appsettings.json` has no value any more, so the check really applies | `PublicSiteOptionsValidator` |
| Sitemap (backend) | `GET /api/public/sitemap.xml`, anonymous, no rate limit. Lists only pages worth indexing: reviewed (published), whose latest revision has content, of a known comune; a tourist tax calculator only when a rate is in force for the comune (A8-12). Plus the hub `/p/affitti-brevi` when at least one page is listed. There is no feature flag on the SEO pages today | `ComplianceSitemapController`, `SeoContentService.BuildComplianceSitemapXmlAsync` |
| Hub | `GET /api/public/content` (same pages as the sitemap) and the web app page `/p/affitti-brevi`, linked from the footer of the CasaZen public pages (not from the hosts' booking sites `/book/*`, which carry the host's brand) | `PublicContentController`, frontend `src/features/public-seo/seo-hub-page.tsx` |
| `/sitemap.xml` on the web app | `vercel.json` rewrites it to the Vercel Function `api/sitemap.ts`, which returns `GET {VITE_API_BASE_URL}/public/sitemap.xml` unchanged. Good answers are cached by the Vercel CDN for 1 hour (`stale-while-revalidate` 1 day); a failure is a `503` with `Retry-After`, never cached | frontend `api/sitemap.ts`, `vercel.json` |
| `/robots.txt` on the web app | Static file generated by `vite build`. `VERCEL_ENV=production`: `Allow: /` and `Sitemap: {VITE_PUBLIC_SITE_URL}/sitemap.xml`. Any other build (Vercel preview, the `develop` test deployment, local, CI): `Disallow: /`. A production build without a valid `VITE_PUBLIC_SITE_URL` (https, site root) **fails** | frontend `src/config/robots-txt.ts`, `vite.config.ts` |
| SPA fallback | The catch-all rewrite to `index.html` excludes `/robots.txt` and `/sitemap.xml`: they never answer HTML with 200 | frontend `vercel.json`, `src/test/vercel-routing.test.ts` |
| CORS | The origin of `App__PublicSiteBaseUrl` is always allowed; `Cors__AllowedOrigins` lists only the other origins | [`cors-security-headers.md`](cors-security-headers.md) |
| CSP | Unchanged: the web app refers to its own origin only as `'self'`, so the policy follows any domain | frontend `vercel.json` |
| Old sitemap | `/sitemap-compliance.xml` on the API host (URLs of another host, declared nowhere) is removed | — |

### Why a function for the sitemap and a build-time robots.txt

- A plain rewrite in `vercel.json` to the backend would need the API domain written in the file (against D3), and the
  same file serves the preview deployments (test API) and production (production API). The function reads
  `VITE_API_BASE_URL` of its own environment at runtime.
- A sitemap generated at build time would be stale until the next frontend deploy (pages are published from the admin,
  on the backend) and would make every build depend on the API being up. The function is always current and the CDN
  cache keeps the load on the API negligible.
- `robots.txt` must never depend on the API: Google treats a `5xx` on `robots.txt` as "do not crawl the site". Built
  from `VERCEL_ENV`, it needs no variable to keep preview and test deployments out of the index.

## 1. Choose the public domain

The domain is a product decision (not taken in code). Once chosen:

1. Vercel → project → **Settings → Domains**: add it and assign it to **Production** (branch `main`). Follow the DNS
   records Vercel shows, wait for the certificate.
2. Decide what the other names do (e.g. the apex redirecting to `www`, or the old `*.vercel.app` production URL):
   Vercel → Domains → **Redirect to** the chosen domain, so only one host serves the pages.

## 2. Variables

Set them **before** the release reaches `main`: the production API does not start without `App__PublicSiteBaseUrl`
(the value that used to be committed in `appsettings.json` is gone), and the production web app build fails without
`VITE_PUBLIC_SITE_URL`.

Railway (backend), per environment:

| Variable | test | production |
|---|---|---|
| `App__PublicSiteBaseUrl` | `https://<web app URL of the develop deployment>` | `https://<public domain>` |
| `Seo__PublicBaseUrl` | unset | unset (or exactly the same value as `App__PublicSiteBaseUrl`) |
| `Cors__AllowedOrigins` | other web app origins of the environment, if any | other origins, if any (the public domain is already allowed) |

Vercel (frontend) → Settings → Environment Variables:

| Variable | Preview (develop / PR) | Production (main) |
|---|---|---|
| `VITE_PUBLIC_SITE_URL` | not needed (robots.txt is `Disallow: /`) | `https://<public domain>`, **the same value** as Railway production `App__PublicSiteBaseUrl`, scheme and host only |
| `VITE_API_BASE_URL` | already set (test API) | already set (production API); the sitemap function also reads it at runtime |

Vercel → Settings → Environment Variables → **Automatically expose System Environment Variables** must stay on (the
default): the build reads `VERCEL_ENV` from it. After changing a variable, redeploy (Deployments → Redeploy).

## 3. Checks after a deploy

```bash
SITE=https://<public domain>
API=https://<railway url of production>

# robots.txt: text, indexing allowed, sitemap on the public domain
curl -sS -o /dev/null -w "%{http_code} %{content_type}\n" "$SITE/robots.txt"   # 200 text/plain…
curl -sS "$SITE/robots.txt"          # User-agent: * / Allow: / / Sitemap: https://<public domain>/sitemap.xml

# sitemap.xml: XML, cached, every URL on the public domain
curl -sS -D - -o /tmp/sitemap.xml "$SITE/sitemap.xml" | grep -iE "^HTTP|^content-type|^cache-control"
grep -o "<loc>[^<]*</loc>" /tmp/sitemap.xml | grep -v "<loc>$SITE/" && echo "WRONG HOST" || echo "all URLs on $SITE"

# canonical of a published page = the same URL on the public domain
curl -sS "$API/api/public/content" | grep -o '"canonicalUrl":"[^"]*"'
curl -sS "$API/api/public/content/affitti-brevi/<region>/<comune>" | grep -o '"canonicalUrl":"[^"]*"'

# CORS: the public domain may call the API (answer contains access-control-allow-origin: $SITE)
curl -si -X OPTIONS "$API/api/public/content" -H "Origin: $SITE" \
  -H "Access-Control-Request-Method: GET" | grep -i "^access-control-allow-origin"
```

In the browser: open `$SITE/p/affitti-brevi` (list of the published pages, or "no guides published yet"), follow a
link, check the footer link "Guide per gli host" on a `/p/…` page.

Preview / test deployment: `curl -sS https://<develop deployment URL>/robots.txt` must print `Disallow: /`. If Vercel
Deployment Protection is on, open the URL in a logged-in browser instead.

## 4. Google Search Console

1. <https://search.google.com/search-console> → **Add property** → **Domain** → the public domain (covers `http`,
   `https` and every subdomain). Verify with the DNS **TXT** record Google shows, at the DNS provider of the domain.
2. **Sitemaps** → submit `https://<public domain>/sitemap.xml`. The status must become **Success**; "Discovered
   pages" equals the number of `<loc>` of section 3.
3. **URL inspection** → `https://<public domain>/p/affitti-brevi` → **Test live URL**: the rendered page shows the
   list, and "User-declared canonical" is the same URL. Repeat for one guide.
4. Never add the preview or test deployments: they are `Disallow: /`.
5. If the old `…/sitemap-compliance.xml` of the API host was ever submitted, remove it (Sitemaps → ⋮ → Remove).

## 5. Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| Railway deploy log: `App__PublicSiteBaseUrl is missing or invalid` | variable not set (or not an absolute https URL) | set it (section 2), Railway keeps the previous deployment meanwhile |
| Railway deploy log: `Seo__PublicBaseUrl differs from App__PublicSiteBaseUrl` | both set with different values | delete `Seo__PublicBaseUrl` |
| Vercel build log: `VITE_PUBLIC_SITE_URL is missing` / `must use https` / `must be the site root` | production variable missing or with a path | set `https://<public domain>` on Production, redeploy |
| `/sitemap.xml` answers `503` | API down, or `VITE_API_BASE_URL` wrong on that Vercel environment | `curl "$API/api/public/sitemap.xml"`; Vercel → Deployments → the deployment → **Functions** / logs show `sitemap.xml unavailable: …` |
| Sitemap URLs on another host | `App__PublicSiteBaseUrl` of that Railway environment is not the public domain | fix it; the CDN refreshes the sitemap within an hour (or redeploy the web app) |
| Production `robots.txt` says `Disallow: /` | the build did not see `VERCEL_ENV=production` | turn on "Automatically expose System Environment Variables", redeploy |
| Sitemap with no `<url>` / hub empty | no reviewed page with content yet; calculators also need a tourist tax rate in force | publish pages from the SEO admin; rates: [`tourist-tax-rates.md`](tourist-tax-rates.md) |
| The web app on the public domain gets CORS errors | the domain in the browser is not the one in `App__PublicSiteBaseUrl` (e.g. apex vs `www`) | redirect the other names to the chosen domain (section 1), or add the extra origin to `Cors__AllowedOrigins` |

## Out of scope

- The `/p/*` pages are rendered in the browser (no prerender): `og:url`, JSON-LD, `noindex` on "not found" pages and
  the sitemaps of the hosts' booking sites are task BK-15 (A8-09, A8-29).
- `GET /api/public/sitemap.xml` also answers on the API host (the function needs it); it is declared nowhere.
