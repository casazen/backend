## Product Architect — Round 1 Response

**Vote**: OBJECT

**Reasoning**:
Business framing, phase intent, and spec format are sound, and the macro-spec index maps cleanly to `Sessions/specs/`. But the draft's **Phase 0 baseline is materially stale** and that error propagates into wrong dependency ordering and spec sizing. The draft inherited the docs' "14 entities / 12 controllers / 7 jobs / STR-focused" figures as [FACT]; the actual codebase has **22 entities, 16 controllers, 10 jobs**, a working **context-scoped RBAC** (`AppContext` / `UserContextMembership` / `Role` / `RolePermission` + `RequireContext:{context}:{permission}` policy builder), and a **substantially built LTR lease subsystem** (`LeaseContract`, `LeaseRegistration` for RLI via Openapi.it Docuengine, `Party`, `LeaseEvent`, `LeasesController` with create→e-sign→RLI-register→receipt, plus `LeaseSignStatusPollingJob`, `LeaseRegistrationStatusPollingJob`, `ESignWebhookJob`). So Phase 3 is largely **already implemented**, independent of Phase 1, and can ship far earlier. Conversely `spec-direct-booking-engine` is **under-scoped**: anonymous search returns the raw `Property` entity and there is no public booking/guest-checkout path, so it is a full epic, not a one-cycle shortcut.

**Details**:
- **Per-phase feasibility**: Phase 0 → blocked (inaccurate baseline; SQL Server vs actual Supabase Postgres; omits LTR + context-RBAC). Phase 1 → feasible but needs-split (billing genuinely net-new). Phase 2 → feasible, greenfield, large (no Conversation/Message entity; needs async webhook ingestion job). Phase 3 → mis-scoped + mis-ordered (lease/e-sign/RLI already built; reframe to complete+verify, pull parallel to Phase 1). Phase 4 → marketplace needs Stripe Connect (different from current single-account StripeGateway). Phase 5 → feasible, far out.
- **Macro-spec recommendations**: SPLIT `spec-direct-booking-engine` → `spec-public-booking-readmodel` + `spec-direct-checkout` + `spec-branded-booking-site`. SPLIT `spec-multi-tenant-orgs` → `spec-tenant-boundary` (Phase 1: `OrgId` FK on Property/Booking/LeaseContract/Payment + plan entitlement) + `spec-org-seats-collaboration` (Phase 2). RESCOPE LTR → `spec-ltr-recurring-rent` (real gap: no recurring-rent ledger/job), `spec-ltr-frontend`, LTR verification spec — referencing real entities, move to ~Phase 1.5.
- **Architectural risks**: tenant-boundary retrofit cost if deferred (rewrite every OwnerId-scoped query); anonymous `/properties/search` returns full `Property` incl. `OwnerId` under `[AllowAnonymous]` → public read-model/DTO mandatory (GDPR → Legal); inbox/AI must stay async/off-request (Hangfire) per 3s webhook rule; direct-checkout must enqueue Alloggiati + compute tourist tax at quote time, never inline; interface is `IChannelAdapter` (+ `ChannelFactory`), not `IOtaAdapter`.
- **Answer Q1 (billing/multi-tenancy)**: keep `spec-saas-billing` as Phase 1 blocker (zero subscription/plan/entitlement/Checkout primitives exist). Don't fully defer multi-tenancy — split: Phase 1 must ship the tenant boundary (OrgId + query scoping + plan entitlement); defer seats/invitations to Phase 2 (cheap — AppContext/UserContextMembership/RequireContext already exist). Deferring the boundary itself is the expensive mistake.
- **Answer Q2 (search+Stripe shortcut)**: No — genuine but thin seed, not a shortcut. (1) search returns raw entity → public read-model needed; (2) no public/guest booking path (BookingController.Create behind PropertyOwner + RequireContext); (3) no guest checkout (PaymentsController charges pre-existing record, no Stripe Checkout Session); (4) SPA is authenticated owner console → branded public site is a new FE surface. Hence the 3-way split.
- **Resolution conditions (→ APPROVE)**: (1) correct Phase 0 to 22 entities/16 controllers/10 jobs + Supabase Postgres + list LTR & context-RBAC; (2) rescope/reorder LTR to complete+verify, move parallel to Phase 1; (3) split direct-booking-engine; (4) split multi-tenant-orgs (keep saas-billing Phase 1); (5) add entities + async job to unified-inbox; (6) fix IChannelAdapter + doc-drift note.
