### 4. Verdetto

**Completamento reale stimato dell'area: ~30%** (app host ~40%, push ~30%, harness GJ come gate ~15%, app fornitore nativa 0% (Fase 2)).

L'app host Expo ha lo scheletro giusto: schermate calendario, dettaglio, richiesta fornitore, segna pagato e check-out, collegate agli stessi endpoint del web (`host.api.ts:13-92`). Il percorso `mark-paid` è l'unico davvero end-to-end. Tre blocchi rendono però l'app inutilizzabile fuori dall'ambiente dello sviluppatore. Il login nativo Auth0 è rotto: le run usavano un token web iniettato in `__DEV__`. La build di release punta a `localhost` con un projectId EAS fittizio. Le push non possono essere registrate, e il backend che le invia inonda l'host di alert ogni ora senza deduplica. A questo si aggiungono difetti funzionali verificabili: share link errato, blocchi iCal cliccabili verso un 404, mese calendario troncato in UTC+2, errori mostrati come "vuoto", nessun logout né refresh token. Soprattutto, la tassonomia delle categorie impedisce di trovare qualunque fornitore attivato dalla UI reale. Il Golden Journey non è un gate: in CI gira solo una variante mockata con assert tautologici, la suite Maestro è un `echo` e `e2e.yml` è un workflow non valido che fallisce senza eseguire job. I test M5, M6 e M7 passano anche con la funzionalità rotta: M7 è passato storicamente su un badge verde hardcoded. I verdetti "GOAL_RAGGIUNTO" dei report precedenti vanno quindi considerati non validi.
